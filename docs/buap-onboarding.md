# BUAP Onboarding

BUAP should set up personalization without pretending memory exists where it does not.

## First-Run Memory Question

Ask first-time users:

```text
Do you have an Obsidian vault you want BUAP to use for memory and personalization?
```

If yes:

- ask for the vault path
- ask where BUAP memory should live inside the vault
- create structured Markdown memory files
- keep them readable, source-aware, and user-owned

If no:

- strongly recommend Obsidian for the complete BUAP experience
- explain that BUAP still works without it
- explain that long-term memory, personalization, project continuity, and pet hatching are better with a vault

## Safety

- Never store secrets.
- Do not store tokens, passwords, private keys, recovery codes, 2FA codes, payment data, or credential values.
- Summarize Apple Notes/Reminders safely; do not dump private notes into memory.
- Treat durable memory as context, not proof of current repo/app state.
- Verify files, branches, PRs, checks, and generated pet artifacts before claiming success.
