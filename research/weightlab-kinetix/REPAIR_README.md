# WeightLab v0.6 — Bounded Neural Repair & Real Failure Telemetry

The paper's 51-statement Kinetix patch succeeds on the nominal car ramp but fails under 50% friction and 125% gravity (eight independent action-seed episodes for each setting). This research module adds trajectories and a reproducible assistant-authored, bounded parameter search.

## Reproduced architecture

Extends existing `physics_rollout.py`, `reproduce.py` and `generalization.py`. Loads the **same released model**, pinned by the prior asset verification, and simulates the same official geometry under prospectively specified physics variations. No generated environment, artificial reward, or mock model.

- `--stage diagnostic`: record body and green wheel trajectories and proximity to red-shape centres at 4-step cadence, including terminal physics reward, in nominal, low-friction and high-gravity conditions.
- `--stage search`: evaluate a fixed manifest of 19 assistant-designed candidate configurations (including unchanged published network). The editable region is **at most two `actor0.b` scalar values** within the original override circuit. The original network and other parameters remain untouched. Each candidate is scored against three *known development* conditions, one episode each. Require strictly more success than the unchanged published patch and no nominal regression before selecting a candidate. No holdout information informs selection.
- `--stage holdout`: if development found a better candidate, run it against the unchanged published model on 60% friction, 115% gravity and combined 80%-friction/110%-gravity conditions; four paired episodes per condition. A candidate is *not* promoted to a live agent, even if it passes. If none improves, **holdout is left unexecuted**.

## Integrity and limitations

The manifest and proposed scalar edits are authored by an assistant, then evaluated by code, **not generated by a separate LLM invocation**. The dev sweep is a limited, coarse hypothesis search, not autonomous generalized neural repair. The reserved holdout was specified before the first search run; it only tests a single fixed level under new parameter shifts, with small sample sizes.

Trajectory `nearest_red_center_distance` is strictly a centre-distance proxy, **not a verified contact manifold**. Kinetix's actual `GoalR` flag and negative terminal reward are recorded separately; avoid asserting a specific polygon collision without a collision-pair trace.

The script outputs and candidate checksums are research evidence. **No weight deployment, self-reward, privileged BUAP action or automatic promotion occurs.** Holdout results are not permitted to revise this v0.6 search manifest; subsequent work must establish new reserved conditions.

## Reproduction

```bash
python -m pip install 'kinetix-env==3.0.2' 'numpy==2.3.4'
python -m unittest discover -v -s research/weightlab-kinetix/test
python research/weightlab-kinetix/repair_experiment.py --stage diagnostic --output kinetix-repair-diagnostics.json
python research/weightlab-kinetix/repair_experiment.py --stage search --output kinetix-repair-development.json
python research/weightlab-kinetix/repair_experiment.py --stage holdout --output kinetix-repair-holdout.json
```

GitHub CI executes this with the official Kinetix package and posts raw JSON artifacts whether the candidate passes or fails. Restrict the interpretation to results actually measured in the CI job.
